# P18B Native Content Management Plan

- Status: Approved
- Document Role: Current focused native content management integration plan
- Authority Level: Execution below full-product and P18A specifications
- Applies To: Main assembly, Hub content panel, pack activation and physical gameplay save isolation
- Owner: Project integration lead
- Depends On: `AGENTS.md`, `docs/superpowers/specs/2026-10-05-plane-walker-p18a-local-content-management-design.md`
- Last Verified: 2026-10-05
- Approval Basis: Standing Project Authorization in `AGENTS.md`
- Exit Gate: Real Main consumes selected pack specs, Hub commands install and manage them, gameplay uses isolated durable domains, and active adventures refuse mutation

1. Establish a failing actual Main integration fixture for install, activation,
   reload, physical Base preservation, isolated Profile continuation and run lock.
2. Configure the P18A manager before child Host boot. Validate the entire selected
   pack list again through the existing Registry inside the real Facade assembly.
   Cold checkpoint and future-run assemblies retain the same selected pack specs.
3. Extend explicit GameState Profile activation with a validated save domain.
   Legacy import and reviewed Base compatibility remain scoped to Base; local
   packages use a distinct Profile and content snapshot without copying rewards.
4. Add a localized, controller-focusable Hub content panel with local directory
   install, package checkboxes, refresh and disabled-only uninstall. Active runs,
   training and pending credits lock management through an authoritative callback.
5. Commit selection before scene reload. A real scene restart loads exactly the
   retained selected bytes, Registry and domain. Refused mutations preserve state.
6. Verify actual EXPANSION launch, physical checkpoint, Base byte preservation,
   returning to Base, cold selection restore, native layouts and packed resources.
   External storefront ownership and arbitrary executable Mods remain outside
   this data-only boundary.
