# 8.5 系统功能与运营规划

> 《Plane Walker: Chronicles of Collapse》系统功能与运营规划设计文档
> 平台：Steam PC | 类型：Roguelike Action | 视角：2.5D俯视角
> 五种武器：剑/弓/枪/杖/拳套 | 核心机制：时间操控 | 地牢层数：5层

---

## 8.5.1 存档系统

### 8.5.1.1 存档内容清单

| 数据类别 | 具体内容 | 说明 |
|---------|---------|------|
| 玩家基础数据 | 当前HP/MP/经验值/等级/金币 | 每次数值变化即时记录 |
| 武器与装备 | 当前武器类型/强化等级/附加属性/装备槽位 | 含所有背包内武器 |
| 道具与消耗品 | 持有道具ID列表/数量/使用状态 | 含时间操控相关道具 |
| Blessing/Curse | 当前生效的Blessing ID列表/Curse ID列表/叠加层数 | 按获取顺序排列 |
| 地牢进度 | 当前层数(1-5)/当前房间ID/已探索房间集合/已解锁门列表 | 房间级精度 |
| 种子信息 | 本局种子值/随机数生成器状态 | 用于回放和每日挑战 |
| 统计数据 | 总击杀数/各武器击杀数/死亡次数/通关次数/总游戏时长/最长连胜 | 累计统计 |
| 成就进度 | 已解锁成就ID列表/成就完成进度 | 与Steam成就同步 |
| 解锁内容 | 已解锁武器皮肤/角色外观/图鉴条目/音乐 | 永久进度 |
| 每日挑战数据 | 当日挑战ID/当日成绩/当日尝试次数 | 独立于主存档 |
| 设置数据 | 音量/画面/键位/语言/UI缩放等全局设置 | 全局跨存档共享 |
| 时间操控状态 | 时间回溯剩余次数/当前时间减速倍率/冷却计时 | 战斗中高频更新 |

### 8.5.1.2 自动存档触发时机

| 触发事件 | 存档范围 | 优先级 | 说明 |
|---------|---------|--------|------|
| 房间切换（进入新房间） | 全量存档 | 最高 | 通过房间出口触发，写入前做原子性校验 |
| 获得道具/Blessing/Curse | 全量存档 | 高 | 拾取动画结束后500ms内写入 |
| Boss击杀后 | 全量存档 | 高 | Boss死亡动画结束后立即写入 |
| 层级切换（进入新层） | 全量存档 | 高 | 层级转场动画期间写入 |
| 玩家升级 | 增量存档 | 中 | 数值变化后立即写入 |
| 时间操控使用 | 增量存档 | 中 | 每次时间回溯/减速触发后写入 |
| 每5分钟定时 | 全量存档 | 中 | 后台线程执行，不阻塞主线程 |
| 游戏暂停 | 增量存档 | 中 | 暂停菜单打开时写入 |
| 退出游戏 | 全量存档 | 最高 | 监听Application.Quit信号，确保写入完成 |
| 异常崩溃恢复 | 仅统计+设置 | 低 | 每5分钟定时存档作为崩溃恢复点 |

**存档写入原则：**
- 采用"写临时文件→校验→重命名"的原子写入模式，避免写入中断导致损坏
- 房间切换时强制等待存档完成再加载新房间（确保不超过100ms）
- 增量存档仅更新变化字段，全量存档重写整个存档文件

### 8.5.1.4 多存档槽设计

| 存档槽 | 用途 | 特殊规则 |
|-------|------|---------|
| 槽位1 | 常规游戏 | 标准Roguelike存档，死亡后可选择性保留统计和解锁 |
| 槽位2 | 常规游戏 | 同上 |
| 槽位3 | 常规游戏 | 同上 |
| 每日挑战槽 | 每日挑战专用 | 每日0:00(UTC+8)自动重置，无法手动删除，仅保留当日数据 |

**存档槽UI设计：**
- 主菜单展示3个存档槽卡片，每个卡片显示：角色等级、当前层数、武器类型图标、游戏时长、最后保存时间
- 每日挑战槽在主菜单以独立入口展示，显示：当日挑战描述、当日最佳成绩、剩余尝试次数
- 3个常规存档槽可自由选择开始新游戏或继续
- 死亡后存档标记为"已结束"，可选择"重新开始"覆盖当前槽位

**存档槽互斥规则：**
- 同一Steam账号同一时刻只能有一个槽位处于游戏中
- 切换存档槽需返回主菜单
- 每日挑战可与常规存档并行（每日挑战入口独立）

### 8.5.1.5 Steam Cloud同步规则

**同步数据范围：**

| 数据 | 是否同步 | 说明 |
|------|---------|------|
| 存档文件(slot_1~3) | 是 | 含主数据+备份 |
| 每日挑战存档 | 是 | 确保跨设备参与每日挑战 |
| 全局设置(画面/音频/语言) | 是 | 保持跨设备体验一致 |
| 键位配置 | 是 | 保持操作习惯一致 |
| 全局统计数据 | 是 | 累计成就相关数据 |
| 成就进度 | 是 | 与Steam成就系统双重同步 |
| 录像文件 | 否 | 文件过大，仅本地存储 |
| 截图 | 否 | 使用Steam截图系统管理 |

**Steam Cloud配额规划：**
- 总配额申请：200MB/用户
- 3个存档槽 × 2MB(主+备份) = 12MB
- 每日挑战存档 × 2MB = 2MB
- 设置+统计 = 1MB
- 预留缓冲 = 185MB

**冲突处理策略：**
1. 检测时机：游戏启动时下载云端存档、游戏退出时上传本地存档
2. 冲突判定：本地`last_saved_at`与云端`last_saved_at`不一致且本地有修改
3. 冲突解决UI：
   - 弹出对话框展示两份存档的元信息（时间、层数、等级、时长）
   - 选项："使用本地存档"/"使用云端存档"/"查看详情"
   - 默认高亮较新的存档
4. 自动合并：设置类数据采用"最新覆盖"策略，不做合并
5. 防止数据丢失：被覆盖的存档自动备份为`conflict_backup_<timestamp>.mpk`

### 8.5.1.6 存档损坏检测和恢复

**检测机制：**
1. **Header校验：** 读取文件头magic number "PWCS"，不匹配则标记为损坏
2. **Checksum校验：** Header中存储SHA-256校验和，加载时重新计算比对
3. **版本校验：** 检查存档版本号与当前游戏版本兼容性
4. **MessagePack反序列化：** 尝试反序列化，失败则标记为损坏
5. **逻辑校验：** 反序列化后检查关键字段完整性（HP>0、层数1-5、种子合法等）

**恢复策略：**
```
加载存档流程：
1. 尝试加载 save_data.mpk
   ├─ 成功 → 校验checksum → 校验逻辑字段 → 加载成功
   └─ 失败 → 进入恢复流程
2. 尝试加载 save_backup_1.mpk（上一个存档点）
   ├─ 成功 → 提示玩家"检测到存档异常，已恢复至上一存档点(时间戳)"
   └─ 失败 → 继续恢复
3. 尝试加载 save_backup_2.mpk（上上个存档点）
   ├─ 成功 → 提示玩家"检测到存档异常，已恢复至较早存档点(时间戳)"
   └─ 失败 → 继续恢复
4. 尝试从Steam Cloud下载云端存档
   ├─ 成功 → 提示"本地存档损坏，已从云端恢复"
   └─ 失败 → 最终兜底
5. 提示玩家"存档无法恢复，将重置该存档槽。统计数据和成就不受影响"
   - 保留全局统计数据和成就进度
   - 重置该槽位为空槽
```

**备份轮转规则：**
- 每次全量存档时，当前`save_data.mpk`先复制为`save_backup_1.mpk`
- 原`save_backup_1.mpk`复制为`save_backup_2.mpk`（覆盖旧备份2）
- 始终保留最近2个存档点的备份

### 8.5.1.7 存档加密/防篡改

**加密方案：**
- 算法：AES-256-GCM（认证加密，防篡改+保密）
- 密钥管理：
  - 游戏编译时嵌入混淆密钥（非明文存储，使用XOR+位移混淆）
  - 密钥分两段存储在代码不同位置，运行时拼接
  - 每个存档文件使用派生密钥 = SHA256(主密钥 + slot_id + salt)
  - salt存储在文件Header中，不加密
- 完整性：GCM模式自带认证标签，任何篡改都会导致解密失败

**防篡改策略层级：**

| 策略 | 说明 | 检测时机 |
|------|------|---------|
| AES-GCM认证标签 | 任何字节修改导致解密失败 | 加载时 |
| SHA-256校验和 | Header中存储完整数据哈希 | 加载时 |
| 逻辑范围校验 | HP不超过最大值、金币不超上限、层数1-5 | 加载时 |
| 时间线校验 | 存档保存时间必须>=创建时间、<=当前时间 | 加载时 |
| 运行时内存校验 | 关键数值(HP/金币/等级)每隔60秒校验内存值合理性 | 游戏中 |
| 统计一致性 | 击杀数>=各武器击杀数之和、死亡数<=尝试次数 | 加载时 |

**作弊检测与处理：**
- 解密失败 → 标记存档损坏，走恢复流程
- 逻辑校验失败 → 提示"检测到存档数据异常"，标记该存档为"受污染"
- 受污染存档：可继续游玩，但**排行榜提交无效**、**成就解锁无效**
- 受污染标记存储在存档Header中，不可通过修改存档清除（加密保护）

### 8.5.2.4 键位冲突检测

**冲突规则：**

| 冲突类型 | 严重级别 | 提示方式 | 处理 |
|---------|---------|---------|------|
| 同一按键绑定到两个操作 | 错误(红) | 高亮冲突按键，弹出提示框 | 不允许保存，必须解决 |
| 互斥操作绑定相近按键（如攻击与闪避） | 警告(黄) | 底部警告栏 | 允许保存但强烈建议修改 |
| 组合键与单键冲突（如Shift+A与A） | 警告(黄) | 底部警告栏 | 允许保存但提示可能误触 |
| 修饰键冲突（两个操作都用Shift） | 警告(黄) | 底部警告栏 | 允许保存 |
| 手柄同按键双绑定 | 错误(红) | 高亮冲突按键 | 不允许保存 |

**互斥操作对（需警告）：**
- 普通攻击 ↔ 闪避
- 时间回溯 ↔ 时间减速
- 切换武器上一把 ↔ 切换武器下一把
- 暂停菜单 ↔ 任何战斗操作

**冲突检测算法：**
```
for each action_a in all_actions:
    for each action_b in all_actions (where b > a):
        if action_a.key == action_b.key:
            if is_error_conflict(action_a, action_b):
                mark_error(action_a, action_b)
            else:
                mark_warning(action_a, action_b)
```

### 8.5.4.3 可Mod化内容

| 内容类型 | Mod方式 | 限制 | 示例 |
|---------|--------|------|------|
| 道具数据 | 修改/新增JSON | 数值在合理范围内(±50%基础值) | 新增道具"时间沙漏" |
| Blessing数据 | 修改/新增JSON | 仅支持已有效果类型组合 | 新Blessing"时空共鸣" |
| Curse数据 | 修改/新增JSON | 仅支持已有效果类型组合 | 新Curse"时间裂缝" |
| 武器属性 | 修改JSON | 攻击力±30%、速度±20% | 增强剑系武器 |
| 武器皮肤 | 替换Sprite | 尺寸必须匹配原规格 | 剑的新外观 |
| 角色皮肤 | 替换Sprite | 尺寸必须匹配原规格 | 角色换色 |
| 音效替换 | 替换WAV/OGG | 采样率/时长必须匹配 | 替换攻击音效 |
| BGM替换 | 替换OGG | 时长≥30秒，无缝循环 | 替换Boss战BGM |
| UI主题 | JSON+Sprite包 | 仅改变视觉，不改变布局 | 暗色主题 |
| 地牢房间事件 | JSON配置 | 仅支持已有事件模板 | 修改商店道具池 |
| 翻译文本 | 修改L10n JSON | 不得增减占位符 | 社区翻译 |

### 8.5.4.4 不可Mod化内容

| 内容 | 原因 | 说明 |
|------|------|------|
| 核心战斗逻辑 | 防作弊/平衡性 | 伤害计算公式、无敌帧、碰撞检测不可修改 |
| 网络通信 | 安全性 | 排行榜上传、Steam API调用不可拦截 |
| 成就系统 | 防作弊 | 成就解锁条件不可修改 |
| 存档系统 | 数据安全 | 存档读写不可修改 |
| 时间操控核心逻辑 | 游戏特色 | 回溯/减速的核心机制不可修改 |
| 地牢生成算法 | 公平性 | 种子→地牢映射不可修改 |
| 排行榜提交 | 防作弊 | 任何Mod加载时禁止排行榜提交 |
| 新武器类型 | 开发成本 | 无法通过Mod新增完全新的武器动作集 |
| 新敌人行为树 | 复杂度 | 无法通过Mod新增敌人AI逻辑 |
| 新Boss | 复杂度 | Boss涉及动画/逻辑/特效，无法纯数据驱动 |

### 8.5.4.5 Steam Workshop集成方案

**Workshop物品类型：**
- 游戏内道具Mod（数据类）
- 皮肤Mod（资源类）
- UI主题Mod（混合类）
- 音效替换Mod（资源类）
- 翻译Mod（文本类）
- 回放录像（见8.5.6）

**上传流程：**
1. Mod作者在游戏内"Mod管理器"中点击"上传到Workshop"
2. 游戏验证Mod文件完整性
3. 调用Steam Workshop API创建Workshop项目
4. 上传Mod文件+预览图+描述
5. Workshop审核通过后公开

**下载/订阅流程：**
1. 玩家在Steam Workshop浏览/订阅Mod
2. 游戏启动时自动下载已订阅的Mod
3. 下载完成后在游戏内"Mod管理器"中启用/禁用
4. 启用Mod时显示警告："启用Mod将禁用排行榜和成就"

**Workshop标签系统：**
- 按类型：道具/皮肤/音效/UI/翻译
- 按兼容版本：当前版本号
- 按流行度：最热/最新/最高评分

### 8.5.4.6 Mod审核机制

| 审核阶段 | 审核内容 | 执行方 |
|---------|---------|--------|
| 上传时 | 文件大小(<50MB)、格式校验、恶意代码扫描 | 自动化脚本 |
| 上传时 | mod_info.json完整性、API版本兼容性 | 自动化脚本 |
| 发布前 | 内容合规性(无违规/恶意内容) | 社区审核+开发团队抽检 |
| 运行中 | 玩家举报处理 | 开发团队(48小时内响应) |

**自动化扫描项：**
- 文件类型白名单：.json / .png / .wav / .ogg / .gd(有限) / .tscn(有限) / .tres(有限)
- 代码Mod：仅允许调用SDK白名单API，禁止System.IO/System.Net等命名空间
- 文件大小：单Mod<50MB，总安装Mod<500MB
- 数值范围：所有数值在基准值±50%范围内

**违规处理：**
- 轻微(数值超限)：自动拒绝上传，提示修改
- 严重(恶意代码)：立即下架+通报Steam+封禁Workshop上传权限
- 玩家举报：48小时内审核，确认违规立即下架

### 8.5.4.7 Mod与成就/排行榜的交互规则

| 场景 | 成就 | 排行榜 | 每日挑战 | 说明 |
|------|------|--------|---------|------|
| 无Mod运行 | 正常解锁 | 正常提交 | 正常参与 | 基准状态 |
| 任何Mod启用 | 禁用解锁 | 禁用提交 | 禁止参与 | 确保公平 |
| 仅皮肤Mod | 禁用解锁 | 禁用提交 | 禁止参与 | 即使纯视觉Mod也禁用，避免争议 |
| 仅翻译Mod | 正常解锁 | 正常提交 | 正常参与 | 翻译Mod不影响游戏性，例外处理 |
| 存档曾启用Mod | 该存档永久禁用成就和排行榜 | — | — | 存档Header标记 |

**实现方式：**
- 游戏启动时检测已启用的Mod列表
- 如果存在非翻译类Mod：设置全局flag `mod_active = true`
- `mod_active = true` 时：
  - 成就系统调用`SteamUserStats.ClearAchievement`不会执行
  - 排行榜上传接口不调用
  - 每日挑战入口灰显
- 存档Header写入`mod_flag: true`，该存档后续即使禁用Mod也保持标记
- 主菜单显示Mod状态指示器（如："[MOD] 成就已禁用"）

## 8.5.6 录像/回放系统

### 8.5.6.1 录像记录内容

**核心原则：记录输入+种子→确定性回放**

| 记录内容 | 数据格式 | 说明 |
|---------|---------|------|
| 种子值 | uint64 | 用于重新生成完全相同的地牢布局 |
| 玩家输入序列 | 每帧输入状态(60fps) | 包含所有按键状态+鼠标位置+鼠标按键 |
| 随机数状态 | RNG状态快照 | 每次关键随机决策时记录RNG状态 |
| 时间戳 | 每帧deltaTime | 确保帧率无关的精确回放 |
| 武器选择 | enum | 初始武器类型 |
| 关键事件标记 | 事件ID+帧号 | Boss战开始/结束、层切换、道具获取、死亡等 |
| 版本号 | string | 游戏版本，用于兼容性检查 |

**每帧输入数据结构：**
```text
ReplayFrame:
  frame_number: uint32        # 帧序号
  movement_flags: uint8       # 方向键位(WASD)，4bit
  action_flags: uint8         # 动作键位(攻击/技能/闪避等)，8bit
  item_flags: uint8           # 道具键位(1234)，4bit
  system_flags: uint8         # 系统键位(暂停/地图等)，8bit
  mouse_x: uint16             # 鼠标X(归一化0~65535)
  mouse_y: uint16             # 鼠标Y(归一化0~65535)
  mouse_buttons: uint8        # 鼠标按键状态，3bit
```

**每帧数据量：** 约 12 bytes
**30分钟游戏录像：** 12 bytes × 60fps × 1800s ≈ 1.24 MB（压缩后约 300-500 KB）

```
     e. 提供反馈入口："描述崩溃前你在做什么？"
```

**自动化测试策略：**

| 测试类型 | 工具 | 频率 | 覆盖范围 |
|---------|------|------|---------|
| 单元测试 | NUnit | 每次提交(CI) | 伤害计算/道具效果/随机数生成/存档序列化 |
| 集成测试 | GUT / gdUnit4 | 每日(CI) | 武器系统/时间操控/地牢生成/商店交互 |
| 回归测试 | 自动化回放 | 每周 | 使用历史录像回放验证无回归 |
| 性能测试 | Godot Profiler + 自研脚本 | 每周 | 各层帧率/内存/加载时间基准 |
| 平台测试 | 手动+自动化 | 每次发布 | Win10/Win11/不同分辨率/DPI |
| 平衡性测试 | Python数据分析脚本 | 每周 | 模拟1000局自动战斗，统计通关率/击杀分布 |
| 兼容性测试 | 手动 | 每次大更新 | 不同GPU(Intel/NVIDIA/AMD)/不同手柄 |

**CI/CD流水线：**
```
代码提交 →
  1. Godot headless导出构建
  2. 运行单元测试(~2分钟)
  3. 运行集成测试(~10分钟)
  4. 代码质量检查(SonarQube)
  5. 构建成功 → 自动部署到Beta分支
  6. 构建失败 → 通知提交者+回滚
  7. 每周自动执行：性能基准测试+平衡性模拟
```

**自动化回放回归测试：**
- 收集10组典型通关录像作为测试用例
- 每次更新后自动回放这些录像
- 比对回放结果与预期结果：
  - 每帧玩家位置偏差 < 0.1单位
  - 最终通关状态一致
  - 统计数据一致
- 偏差超过阈值 → 标记为"回放回归Bug"，高优先级修复
