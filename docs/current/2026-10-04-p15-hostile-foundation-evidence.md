## Delivered Boundaries

`HostileActionContract` validates a closed action record, fifteen handler families and their exact parameter fields, finite geometry, warning/recovery floors, integer frames, bounded schedules, unique hit indices, and deeply isolated normalized data. Unsupported handlers reject; parsing alone does not certify a handler's production implementation.

`HostileActionCoordinator` advances sequential accepted frames through warning, active, recovery, and idle. It freezes quantized source/target geometry, allocates separate generations for each threat primitive, emits one logical scheduled hit for a geometry union, enforces cooldowns, and retires every owned threat on completion or cancellation. Native fact conversion uses the existing strict `HostileTelegraphFact` contract. Restore validates the configured identity/content digest, frame/phase consistency, frozen geometry, generation floors, cooldowns, pause duration, and exactly the scheduled hit claims that should already exist. Stop advances the accepted runtime clock while preserving action state and emits compare-and-swap threat expiry extensions.

`HostileThreatRegistry.extend_fact_through` accepts only an existing source/generation with the exact expected expiry and a strictly later replacement expiry. It revalidates the copied fact and changes no other geometry or identity. Missing, retired, foreign, stale, and shortening requests reject without mutation; existing M1 registry paths remain unchanged.

`LaunchEncounterProfile` validates the five existing profile identities and their exact five-combat/three-elite recipe ID sets. `LaunchEncounterCatalog` resolves those profiles, forty recipe records, and five Boss references using the current ContentRegistry interface. Configuration requires all twenty-two ordinary identities, five Boss identities, ten affix identities, and five profiles, with closed actor/template references and per-wave threat budgets. Selection uses SeedService, respects room templates, and avoids an immediate repeat when another compatible recipe exists. Unknown Launch references return empty definitions.

`launch_encounters.json` now owns the actual five profiles and forty ordered recipes. Each elite roster preserves its designated combat roster, promotes one actor and adds exactly one normal escort; oversized totals split across bounded ordered waves. `LaunchHostileContentSource` reads the actual Enemy/Boss/Affix/Profile/Room files for this inactive adapter. `configure_authored` consumes that source through the same catalog validation. The mutation fixture reads those same files instead of maintaining parallel rosters or threat costs. Actor definitions pass their closed native parsers before canonical scene/floor metadata is derived, and affix definitions are parsed as real records.

Recipe/template validation requires the actual floor compatibility, authored hostile anchor, sixteen-pixel offset grid and room margin, thirty-two-pixel actor separation and sixty-four-pixel Player-entry distance. All ten combat and five elite template identities are covered across the catalog; each profile covers every applicable template, with combat counts `8 / 8 / 10 / 9 / 10`. Actual elite rooms use `elite_primary`, so elite runtime definitions and slot lookup bind that physical anchor. This static data boundary does not certify body collision clearance, reachable routes or the native scene owner's spawn transaction.

`LaunchEncounterRuntime` uses fixed frames for wave delay, continuous warning, spawn requests, and terminal completion. Stable source IDs replace Node instance IDs in its domain roster. Nonterminal life states remain counted. Unique final-death receipts, unacknowledged spawns, and bounded pending projectiles/zones/constructs/links/portals/summons prevent premature completion. Failure and cancellation reject further frames. Strict checkpoints support deterministic mid-combat reconstruction without observable mutation on rejection.

`HostileControlRuntime` owns bounded fixed-frame source maps for Stop, Rift, weakpoint, and vulnerability. Duplicate sources cannot restart lifetimes. Stop sources expire independently; Rift takes the strongest source with a `0.40` movement floor; weakpoint takes the largest active bonus; independent vulnerability sources combine under a `3.0` damage multiplier cap. JSON numeric normalization and strict identity/frame/expiry checks protect checkpoint restoration. Terminal cleanup removes every control source.

`LaunchEnemyRuntime` initially consumed the strict eight-field `EnemyDefinition.runtime_projection`, including the authored closed `mechanisms` map. The current nine-field projection adds authored `collision_radius_px`, validated as finite non-Boolean `[1, 32]` and normalized alongside the other native stats. It implements the Sentinel mechanism using the common coordinator, seeded initial attack staggering, pursuit, the paired sweep, and the default nineteen-pixel retreat over forty-eight accepted action frames. Retreat distance/duration and initial stagger follow authored values; mechanism checkpoint limits follow the same configured values. Its action/control/mechanism checkpoint validates together, and action interruption is distinct from terminal cancellation.

The next inactive Ruins boundary adds unique Health damage facts and two concrete mechanism state machines. With default content, Strider shell closes for `120` accepted frames after a hit, retains its original lifetime on further hits, then exposes for `30` frames with damage multipliers `0.30` and `1.30`. Wraith accumulates damage during its committed detonation warning; `15` damage retires the warning and creates a `30` frame nonattacking, nonmoving stagger. A pre-active lethal Health result cancels the warning. Shell/open duration and multipliers, interrupt threshold, and stagger duration read the validated authored mechanism values. These mechanisms use strict native actor/Health compensation, including rejected incoming damage claims. Elite splitting, support/death payloads, complete kits, and routing remain open; unsupported mechanism requests reject explicitly.

Strider charge begins movement at the first active frame, following its frozen aim at the authored `240` pixels/second and stopping after at most `48` pixels across twelve active frames. Stop postpones action and motion. The native actor predicts real body collisions in test-only mode and seals the ephemeral collided target in its frame ticket. Charge damage requires that exact target contact inside the committed warning corridor; the corridor alone deals no instant damage. Walls and foreign colliders cannot damage the Player. Repeated active-frame contact accepts a no-effect claim instead of duplicating the one `15`-damage hit. Actor displacement, Health, registry and damage claims compensate before an exact-frame retry. Collision Node handles are native transaction state, not persisted Save/Replay state.

Elite Strider automatic selection now prioritizes its eligible shell shock before base actions exhaust the shell lifetime. The shock reserves a once-only claim at warning commitment, binds expenditure to `shell_shock_cycle`, and retains that original lineage if a later authored short shell begins during recovery. Pre-cycle expenditure and committed-action/unspent-cycle checkpoints reject. The actual forty-frame warning, ten active frames and authored eighteen damage with the existing elite `1.25` projection multiplier execute through the native circle/Health effect authority. A real Health hit opens the shell; a real Launch Time Guardian takes that `22.5` damage minus native defense once through its Character damage contract, using a conforming principal source ID without colons. Stop postpones the warning. Native rejected warning reservation compensates the cycle claim and threat registry, then retries with the same action generations. This does not certify affix integration or every elite species.

After the Wraith's complete active detonation, its next prepared domain state is terminal and retires every owned threat. A closed native consumption request retains run/source/frame/action/generation identity. The effect authority accepts it only from the actor's sealed terminal preparation and consumes the real remaining Health through buffered `lose_health`; it creates no fabricated DamageInfo or hit observation. A rejected effect or later World commit restores live Health, active action, claims, registry, and statuses. Accepted publication emits the usual single canonical `hostile_defeat` receipt and the bridge removes the terminal roster before the presentation body retires. This receipt is a native combat fact, not an independently minted material or settlement reward.

`LaunchHostileActor` provides native Sentinel, Strider, Wraith and Moth adapters. It reuses EnemyBase's damage and weapon/status helpers, replaces physics and timer gameplay with accepted-frame preparation/commit/compensation, predicts movement through native collision in test-only mode, and projects the authoritative action into a four-frame raster. Configuration duplicates each body and hurt shape before installing the authored collision radius; one actor's shape changes cannot mutate other scene instances. Its real HealthComponent resolves weakpoint and vulnerability damage. Final Health death clears control/status state and emits one stable encounter receipt; room economy remains an external authority. Its explicit presentation ownership prevents CombatFeedback's legacy generic PixelProxyActor from covering the original native raster.

The native room-motion endpoint validates the real `LaunchRoomScene` and authored room template through `RoomSceneContract`. It requires translation-only transforms, actual rectangular CameraBounds, the authored circular body/hurt geometry, enemy body layer `4`, and world collision mask bit `1`. A deeply isolated descriptor freezes room identity, translated global bounds, radius and native collision layer/mask. Prepared, restored and published native frames recheck the actual room transform, physical CameraBounds and actor geometry. Movement is clipped to the rectangle inset by the authored body radius before collision prediction. Configured Wraith movement bypasses internal colliders inside that limit; an unconfigured Wraith and all other species retain native collisions. This endpoint neither mutates collision masks nor invents an outer physical wall layout.

Native preparation also accepts Health damage already staged by the Player in the same frame. A staged lethal result prepares terminal cancellation and suppresses attacks and burn ticks without publishing a defeat receipt; compensation restores life, group membership, controls, status clocks, and the Health ledger. Only published final Health death starts the bounded `0.2` second presentation retirement and releases the native body. Weapon interruption cancels the current action without terminally cancelling the actor.

`LaunchElementalStatusRuntime` adds complete native compensation snapshots to the existing status implementation. These retain deterministic seed, both slow floors, elapsed tick clocks, ownership, and live burn source/attacker references. They are native transaction records, not persisted Save/Replay seals. Health compensation uses the existing once-only frozen ledger contract; restoring or discarding a checkpoint consumes it.

Health frame transactions now buffer the three typed combat observations alongside native Health signals. Each queued `hit_confirmed` retains its own settled HP, death, weakpoint, and frame context. An optional internal attacker staging callback preserves same-frame Player facts before public publication; the context records whether that observation was staged so the public callback can avoid recording it again. Direct Health calls retain synchronous observation behavior. Rejected finalized publications also discard late queued observations.

`LaunchHostileEffectAuthority` verifies source-sorted native batches against each actor's sealed preparation, validates threat registration/retirement/expiry extensions on an isolated registry, creates immutable DamageInfo plans, and applies real Health damage through geometry unions. Implemented action handlers are melee, native single-hit charge, and Moth projectile volley; other action handlers reject. Implemented mechanisms include authenticated Wraith self-consumption and Moth final-death pool reservation. Native burn ticks retain stable identities and tolerate a released source handle. Burn target validation recognizes the actor's sealed committed displacement. Compensation restores claims, registry, and effect-owned signal buffers; outer actor/Player owners restore Health checkpoints. Publication detaches its batch before callbacks and rejects reentry. Reconfiguration validates payload readiness before replacing the effect run identity or frame, so live-payload rejection leaves the whole aggregate unchanged.

`LaunchHostilePayloadRuntime` owns finite projectile and acid-zone records independently of parent actors. The actual authored Moth volley commits a frozen direction, `192 px/sec` movement, `120` frame TTL and `240 px` maximum range. Independent elite lanes retain root generation plus lane index. Accepted swept contacts validate target geometry; one projectile hit creates an impact pool with radius `13`, lifetime `120` frames and exactly two `3` damage ticks. Final Moth death reserves a fresh generation and a radius `16` pool with `30` full warning frames before one `5` damage pulse. Duplicate lineage, foreign lanes, distant contacts, fabricated live-death checkpoints and malformed trajectory/control state reject. At most `32` projectiles and `12` zones are active; excess eligible reservations retain FIFO pending records. Stop pauses payload travel and lifetime while source lifetimes advance, and Rift keeps the existing `0.40` floor.

`LaunchHostilePayloadAuthority` projects those records through original PNGs and real CharacterBody2D swept collision, using an independent native root outside the validated static room. Strict body/receiver shapes, disabled state, offsets, layers and scale are rechecked along with target descriptors and every predicted collision at commit. A dedicated RiftReceiver observes actual TimeRift Area overlap without making projectile bodies obstacles for the Player. Retired projections remain available until publication; rollback restores their Rift receiver layer as well as trajectory and control sources. The bridge captures the aggregate effects checkpoint before Time, weapon and world actions, so a later whole-frame rejection restores same-frame payload controls and reservations.

Each of four payload children can be freed without a script error or an accepted projection.

## Production Integration Contract

- Action coordinator configuration receives `{id, actor_kind, actions}` and identity `{run_id, hostile_source_id, next_generation_floor, runtime_frame}`. Frame observations are `{runtime_frame, source_position, target_position, facing_direction, target_id}`; points contain exactly numeric `x` and `y`.
- Enemy runtime configuration receives exactly `{id, actor_kind, runtime_kind, max_hp, defense, move_speed, collision_radius_px, actions, mechanisms}` from `EnemyDefinition.runtime_projection`. The species mechanism rules remain owned by `EnemyDefinition`; native runtime repeats that closed validation and consumes the normalized values. This projection is not proof that every authored species mechanism has a native implementation.
- `configure_launch_room_motion(room: Node2D, template: Dictionary) -> Dictionary` installs the validated native room boundary before accepted actor frames begin; `launch_room_motion_snapshot() -> Dictionary` exposes a deep copy. Rebinding, out-of-bounds native placement, stale or freed rooms and changed native geometry/policy reject. `room_motion` inside actor compensation state must match the configured descriptor. Actual dynamic actors must remain outside the validated static room subtree, preserving `RoomSceneContract`'s single root-script rule.
- `request_action` returns JSON-safe `threat_facts`, a root attack generation, cue ID, and handler ID. Convert each fact with `HostileActionCoordinator.native_threat_fact` before native registry registration.
- `advance_frame` returns `hit_facts`, first-active-frame `effect_requests`, `retired_generations`, and `threat_extensions`. The integration authority must apply each scheduled geometry union once through DamageInfo/HealthComponent, dispatch semantic effects only to implemented handlers, and apply Stop expiry extensions transactionally through `extend_fact_through`.
- Encounter configuration receives a resolved encounter and `{run_id, room_id, runtime_frame, encounter_generation}`. `advance_frame(frame, {})` returns `wave_started`, `spawn_warnings`, `spawn_requests`, and `encounter_completed`.
- Production combat principal source IDs must use the existing Character damage contract's allowed segments without `:` (for example `hostile-floor-node-spawn-generation`). The canonical final-death receipt retains its separate `hostile_defeat` receipt format. Current native tests with colon-bearing source IDs do not certify production Player Character damage routing; that integration gate requires real Player damage with conforming source IDs.
- Bind actual actors through `register_spawned(spawn_id, source_id)`. Domain life transitions call `set_life_state`. Final authenticated HealthComponent death receipts call `notify_entity_defeated`; dormant/recovering actors cannot submit a normal death receipt. An authenticated sigil finalization first installs the `FINAL` life state.
- Payload creation/retirement reserves/releases `pending_work`. The bridge owns atomic frame preparation, live effect commit, compensation, and publication; these pure objects do not independently run physics or publish EventBus facts.
- Native actor frame APIs are `prepare_launch_frame(frame, observations) -> {ok, ticket, batch}`, `can_commit_launch_frame(ticket) -> bool`, `commit_launch_frame(ticket) -> bool`, `rollback_launch_frame(ticket) -> bool`, and `publish_launch_frame(ticket) -> bool`. Preparation predicts an isolated domain/status/transform candidate. Commit installs that candidate. It does not apply registered geometry or target damage; the shared effect authority owns those effects.
- Effect APIs are `configure(run_id, runtime_frame) -> bool`, `prepare_effects(batches, context) -> {ok, ticket}`, `can_commit_effects`, `commit_effects -> {ok, resolutions}`, `rollback_effects`, `can_publish_effects`, and `publish_effects`. Bridge protocol aliases are `can_commit`, `commit`, `rollback`, `can_publish`, and `publish_effect_observations`. Context has exactly `run_id`, `runtime_frame`, `threat_registry`, `actors`, and `targets`; batches are source-sorted `{hostile_source_id, batch}` wrappers. `prepared_launch_frame_position` exposes the sealed native prediction without advancing the actor.
- `configure_native_payloads(root: Node2D) -> bool` binds the independent payload projection owner; `payload_snapshot()` and `native_payload_nodes()` expose deep domain state and live native projections. Effects `launch_transaction_snapshot`, `can_restore_launch_transaction_snapshot`, and `restore_launch_transaction_snapshot` compensate payload state before other frame effects. These native checkpoints are not persisted Save/Replay certification. Full room pending-work synchronization must count queued records as well as active projections before native room completion is certified.
- `launch_transaction_snapshot`, `can_restore_launch_transaction_snapshot`, `restore_launch_transaction_snapshot`, and `discard_launch_transaction_snapshot` own native frame-start actor/Health compensation. They are distinct from the prepared actor frame ticket, which only restores domain/status/transform. The bridge must not duplicate the same Health frozen-ledger ownership in another participant.
